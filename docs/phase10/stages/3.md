## 实施期修订(相对冻结契约)

1. **`ensureRunPlan` 预铺缺 seq 赋值的真实 bug(契约 §3.3 未写明的实现细节)**:预铺循环最初 `for _, tpl := range patrolPlanTemplate(...)` 未写 `tpl.Seq` → 5 条行全部 seq=0 落库 → 撞 `UNIQUE(plan_id, seq)`(2067)致**每次 patrol run 建单失败**(新 T1 用例首跑即抓出)。修法:模板不预写 seq,预铺时按序 `tpl.Seq = int64(i+1)`(plan.go;若当时不修,10.3 上线的每一个 patrol run 都会崩 —— T2/T3/T5 全族 + 既有 S 系列回归一起兜住)。
2. **server 层巡检 run 的「模拟完成」**:server 包无 env seam、建单不执行(queue work 关)→ Tsrv-1 用「RunPipeline 建单(真预铺 5 行)→ store.UpdatePlanPhase 直铺 seq1..4 到 ok」模拟 scripted 完成态,再验读端点形状与 status/evidence/时间戳真实流过 HTTP(与 10.2 Srv-4 同思路;状态翻转语义本身由 service T2/T3 覆盖)。
3. **runLedger 对无计划/缺 seq 行的宽容**:`lgStart`/`lgFinish` 对 lg==nil(非流水线 run / 0016 前历史 run)→ no-op;缺该 seq 行 → no-op;`lgFinish` 目标态与现有完全相同(requeue 续跑重复完成)→ no-op —— 机械层收紧不波及无计划 run 的既有语义。
4. **grow 记账幂等 = 按 title 去重**:`appendPlanPhase` 同 title 行已存在 → no-op(跨 requeue/re-entry/同 round 返工不重复 append);终态行补 started/finished=now 记录真实边界,pending 行(planner ask 等未决)留空时间戳 —— 契约 §3.3 的幂等落成实现细节。
5. **二进制冒烟「run 201」措辞修正**:实跑 `POST /pipelines/{id}/run` 返回 **HTTP 200**(apiOK 信封 `{task_id,project_id,pipeline_id,task}`,自 10.1 起为该 handler 定稿语义,projects_api_test.go 既有断言即 StatusOK);契约定稿清单里的「run 201」为写作时不精确,以冻结 handler 契约(api.go 注释 + DTO)为准 —— 验收看点是 run 成功建单 + plan 读回 5 条 pending,两者都过。
6. **机械 pre 快照的时机**:委派前快照不仅含用户既有脏项,还沿用 engineering ensureBaseline 语义排除 agent CLI 运行时残留目录(patrol.go 注释),使 porcelain post−pre 对账聚焦「本次委派净新增」。

## 冻结边界(留给后续子阶段)

- **不做通用计划解释器**:账本只记录两驱动真实边界 + 在真实边界翻状态;10.4 合成进来时把「frontier 合成计划」直接落进同一 task_plan/phase 表(本子阶段是它的落库/观察/审批底座)。
- grow 无预铺 → risk=high engineering run 审批仍只见任务描述不见完整计划(自适应本性诚实边界;完整计划等 10.4 合成,不在 10.3 造伪预铺)。
- OS 直跑 go test/build 的机械验收(engineering 的 build/test 型 run)留未来形态;本子阶段机械层只在 patrol 线性形态(接受 run)。
- 计划账本只服务 RunPipelineAs 建单的顶层流水线 run;手动 createTask / workflow / 拆解子任务(split)天然无 plan(GET 返回 plan:null)。
- 项目/流水线删除不新增 store 步骤(plan 最小 FK task → 任务历史保留即 plan 随任务保留;删除永不碰磁盘)。
- 计划行证据只存引用/摘要(报告 rel/verdict 行/diff 首行等),不整存大产出;报告/执行正文仍存既有 execution/patrol 文件。
- 10.4 高智合成 + 预算 + 凭据,见方向 §八(未开始)。

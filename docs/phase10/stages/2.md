## 实施期修订(相对冻结契约)

1. **契约 §五 Srv-3「预置过去」的精确语义**:cron 只在整分命中 → preseed 须为**已过整分边界**(`time.Now().Truncate(time.Minute)`),不能是 `now-1min` 任意偏移(否则 advance `Next(next)` 落在已过整分,断言 future 失败)。
2. **`globalSettingsDTO` 漏 `schedule_poll_sec`(冒烟抓出)**:service/patch/model 三层都支持 SchedulePollSec,唯独 server 设置回包 DTO 未序列化 → Web 设置行读恒为 undefined、PUT 后不回显 = 只写不回暗角;补 DTO 字段 + toGlobalSettingsDTO + E1 回归断言(GET 默认 0 / PUT 60 回显)。
3. **迁移分两枚(0014 + 0015)**:契约 §四 只列 0014(task.pipeline_id);app_setting.schedule_poll_sec 需独立一枚(0015,只增列 DEFAULT 0)——同批落,sqlc/schema 同步。
4. **server 层巡检 run 的模拟完成**:server 无 env seam、建单不执行 → Srv-4 用「run 建单 → OS 写 `patrol/<id>.md` 真落盘 → st.CompleteTask(result 带 `patrol:` 前缀)」模拟 scripted 完成的巡检 run,再验读端点(与 10.1 G5b 同思路)。
5. **schedule 校验只在写口**:Create/Update 都过 normalizeSchedule(空/off 存原文不调度;非法 ErrInvalid 指引);ListScheduledPipelines 只取 active+schedule!='' 子集,服务器 parse 仍作脏数据防御(清 map 跳过不触发)。

## 冻结边界(留给后续子阶段)

- **只读凭据引用后移(定稿门②)**:巡检无真生产凭据 = fail-closed 不触网,证据来自项目目录内例行检查(build/git 卫生/残留等,检查项 = description);真实凭据注入 + 主机 allowlist 归 10.4+。
- schedule 对三种 kind 都合法(到点 = 复用 RunPipelineAs);ops_patrol 可手动 run(不设 schedule)→ 同入口认领分流。
- 不做 pipeline 其余字段编辑/disable(暂停调度 = schedule 置 ""/off);不做 `code/`/`knowledge/` 子目录实体化(`patrol/` 是 OS 类型化工作目录,不挪用户内容)。
- 重启丢一次命中(scheduleNext 内存态,`Next(now)` 从未来算,不补历史)——单 operator 可接受,记日志。
- 10.3 阶段计划契约通用化 / 10.4 高智合成 + 预算 + 凭据,见方向 §八(未开始)。

- **P1-P10(service,离线本地 bare remote + fake PullPublisher 记录)**:P1 项目机密 CRUD + 双层解析(项目覆盖
  公司 / 删项目 token 落公司回退);P2 issueBranchName prefix+slug;P3 gitAuthEnv(https github 才注入 auth;本地
  origin 零注入);P4 originDefaultBranch symbolic-ref;P5 ensureIssueBranch 幂等;P6 发 PR 端到端(push 后 bare 见
  分支 + CreatePull(owner/repo/title/head/base/body Resolves #N)被调 + pull_request_url/number 落库 + audit
  pr_opened);P7 无项目 token / scripted 静默 skip 不触网;P8 PublishTaskPR 门(未完成/scripted/无 prTarget/无项目
  token → ErrInvalid 指引,不发网络);P9 SyncProject(fixture)issue→task(project_id 归属 + workspace=项目根 +
  engineering);P10 UpdateProjectAs(改名/同目标不动盘/空名 ErrInvalid/重名 ErrConflict/占位仓 clone 认领/带历史
  改挂 ErrInvalid)。
- **GH1-GH4(github,httptest NewClientAt)**:CreatePull 路径/body 透传 + Bearer+Accept vnd.github+json +
  X-GitHub-Api-Version + 201 → Pull{number,html_url};非 201 错误含 HTTP 码;空 token 不发 Authorization;
  DefaultBranch GET /repos/{o}/{r}。
- **R1-R4(server,HTTP 离线真 git)**:R1 PUT project 编辑 200 code_source 仍绑定/desc-only 保 name/未知 404/重名

  人 GitHub merge)**,如实标注边界(同 stages/5 惯例;离线 P6 真 git push 到 bare + fake CreatePull 参数断言 =
  回写半环机械等价)。

## 实施修订(相对契约的落地裁定)

1. **UpdateProject 重名语义与契约 §四 C 行文出入**:契约写 store UNIQUE(company_id,name) 冲突 → ErrInvalid;
   实现按 project create 既有惯例在 service 层 `isUniqueViolation` → **ErrConflict(HTTP 409)**,R1/P10 断言
   409/ErrConflict(与 create 同源同码,Web 编辑弹 409 语义一致)。
2. **写路径仅项目 token = 安全红线**(契约 §一.2 原样):git push + 开 PR 的认证经 `gitAuthEnv` Basic extraheader
   env 一次性注入,不入 argv / 不入 origin;公司只读 token 永不用于写。
3. **finishRun best-effort**:publish 失败/跳过**不阻塞 complete**(任务照常完成不复活,pr_skip/pr_fail 仅审计
   留痕);run 内 publishRunPR 对无 target/scripted/无项目 token 静默 skip 保 run 语义不惊扰;人工重试门
   PublishTaskPR(未完成/scripted/无 target/无 token)全列 ErrInvalid 指引。
4. CLI 零新增命令:编辑走 Web/HTTP 面(service 留 `UpdateProject` human:cli 单点供 CLI/未来直开)。

## 冻结边界(留给后续)

- **live 全链路验收待用户**:真实 PAT 下 Web 填 token → 同步 issue → 认领 run 自动推分支开 PR → 人在 GitHub
  merge(离线等价已由 P1-P10/GH/R 覆盖,回写机械一致)。
- **私有仓库 / 多机**:token 现只经 https://github.com origin 推分支注入;ssh-origin 与私有仓 clone 凭据注入留
  10.6+「凭据注入·主机 allowlist」候选。
- **PR 后段自动化不做**:不代合、不做 merge、不做本地开 PR 前审批 UI(契约 §一 边界;人审在 GitHub 页)。
- **GitHub issue 定时同步 / webhook → 流水线常态化**(通道 B):Phase 6.3 已有 issue→task + 本 10.5 项目级 sync;
  周期性/webhook 触发 engineering run 不属本子阶段。
- **老项目迁移不做**:root_path 不可编辑;repoURL 改挂仅限占位/新目录安全子集(带本地 git 历史拒绝)。
- Phase 10 主路线完结(10.1-10.4 + 两增补:自动代码获取 / PR 回环);剩 **10.6+ 候选**见方向
  [declarative-pipelines.md](../design/declarative-pipelines.md) §八(例行模板化数据化 / OS 机械扩 build·test /
  凭据注入·主机 allowlist),下一工作照 契约 → 实施 → 验证 → 归档 → commit。

## 验证

- `go vet ./...` / `go build ./...` 干净;`go test -count=1 ./...` 全绿(既有用例**零 body 改**,grow/patrol/无
  verify 合成逐字不动)+ `-race`(service)绿;gofmt 本次改动干净;**零 Web diff → 不跑 tsc/vite**(契约边界)。
- **V1** verify go-test PASS 主链:OS_SCRIPT_SYNTH = do → accept(os,`verify: go-test`)→ dispose(manual);项目根带
  已提交 go.mod;fake runner exit 0 → completed `synth: 3 phases executed`;acc evidence 含 `verify go-test: PASS`;
  runner 恰调 1 次(name=go argv=`test ./...` dir=ws);逐相位 ok + eng_complete 审计。
- **V2** verify FAIL → 返工 ≤1 → 仍 FAIL → 相位 fail → 任务 **failed 不复活**(fake 恒非零,输出带 `--- FAIL:
  TestFlaky`);acc evidence 首段含 `verify go-test: FAIL` + 输出首行;runner 调 2 次;do/acc 相位 fail 落账本。
- **V3** verify FAIL → 返工 → PASS(fake fail-once)→ completed;runner 调 2 次;返工放行语义。
- **V4** 词表外 verify(`python-pytest`)→ validate 错 → audit eng_synth_fail → 降级 runEngineering(OS_SCRIPT_TEST/
  REVIEW scripted)→ completed;runner **不触**(0 次);materialized 保持 grow;无 eng_synth。
- **V5** verify 位置约束:judge-accept / do / dispose 上出现 → 计划无效降级(同 V4 断言,不落半成品 upfront)。
- **V6** 残留对账双分支:fake exit 0 且落一个 untracked 临时文件(coverage.out)→ PASS 后该文件被回收、evidence
  `residue cleaned=1`、工作树归净;另一分支 fake 改动已提交 go.mod → verify fail `dirtied tracked file`,不自动回滚
  (工作树保持 dirty 留人/委派处理)。
- **V7** 无 go.mod 门:项目根无 go.mod + verify go-test → accept fail、reason 含 `no go.mod`、runner **不调用**(0 次);
  返工用尽 → 任务 failed;计划合法(go-test 在词表内)不产生 eng_synth_fail。
- **二进制冒烟**:合成 verify 需 frontier 端点合成 → 离线不可达端到端;跑既有回归冒烟(G 族)证明无回归。verify
  live 端到端(真 frontier + Go 项目 + 真 go test 修复后过门)→ **如实标注待用户边界**(同各阶段惯例)。

## 实施修订 / 边界(如实)

- runner 执行是唯一真实 exec:V1-V7 全注入 fake(记录 argv/dir/产出),离线确定性成立;真实 go 只在 live 合成 +
  显式 verify 相位被 OS 执行(本子阶段语义),test 覆盖到的真实命令路径为 `verifyReconcile`/`gitPorcelainSet`/`wsIsGit`
  等既有 git 机械,无新增真实外部进程调用点。
- `runSynthAccept` os 分支由外层 ctx 改传 runCtx(任务时间预算)→ verify 超时语义与任务预算一致;既有相位
  (无 verify)只读三检查走同一 ctx,行为不变(600+ 零 body 改验证)。
- do 相位产出 go.mod 是可返工路径:do 返工可把模块建出来 → 重 verify 过门(V7 门语义;首版不捕获 verify 基线、
  不自动放行 —— 契约 §一.2 诚实边界)。

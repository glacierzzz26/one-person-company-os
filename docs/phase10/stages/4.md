## 实施期修订(相对冻结契约)

1. **runSynthPhases 复活 failed 任务为 completed(生产级 bug,SY3b/SY4-B 首跑抓出)**:engFail 成功返回 nil(=「已处理」:任务已 fail/requeue),原实现 runSynthUnit/runSynthDispose 错误分支直接 `return s.engFail(...)`(nil)→ 循环继续 → 无条件尾 `CompleteTask`(result `synth: 3 phases executed`)把 failed **复活成 completed**。修法:errSynthTerminal 哨兵 + `engFailTerminal`(engFail 成功 → 哨兵);runSynthPhases 收哨兵 → 立即 return nil(停止,绝不补 CompleteTask)。既有 engFail 语义零动(600+ 兜底)。
2. **SY3 空白分支反了(git diff --check 语义)**:`git diff --check` 有空白错误**非零退出** → 原守卫 `err == nil && out != ""` 永不触发(该分支本应 fail 却 pass)。改 `err != nil` 即「查出问题」;相位提交空白检查(HEAD^..HEAD)加 `rev-parse --verify HEAD^` 浅历史守卫(仓库首个提交无 HEAD^ → 跳过不误伤)。
3. **create 请求漏 plan_policy 时 CreatePipelineAs 默认 adaptive 的语义落点**:空 policy → 不调用 SetPipelinePlanPolicy,靠 **DB DEFAULT 'adaptive'** 落列(迁移保证既有行/既有调用全 adaptive);service 只校验非白名单非空值 → ErrInvalid → HTTP 400。
4. **server 无 env seam → Vsrv-1 断言 grow 空态,合成语义留 service**:server 包 engine 恒 live、run 只建单不执行 → GET plan 断言 = 未认领诚实空态(grow+phases 0+plan_policy=synthesize);合成/执行/返工/降级全部 SY* 覆盖(与 10.3 Tsrv-1 同构)。
5. **同项目串行守卫影响 Vsrv-1 双 run**:同一 project 第二个 run 前须 store.CompleteTask 收尾首个任务,否则 409(与 projects_api_test 同 pattern;测试内建任务直铺完成态)。
6. 计划读端点 plan_policy 为 **additive 展示位**(流水线已删/无反链 → 空串),不对既有 plan 断言造成破坏(plan_api_test 的 planViewMirror 未动)。

## 冻结边界(留给后续子阶段)

- **预算/成本/失控轴不做**(定稿门①):预算/成本治理归外部系统,产品不内建计量/单位成本/阶段全局预算;零成本原语保持零。
- **例行模板化数据化(D3)**:patrol 5 段模板 = 例行模板唯一现例(硬编码);「任意工程 run 登记固定例行模板」做成数据实体/作者面 = 后续。合成与模板共用「先铺 upfront 账本 + 通用逐相位驱动」,模板进来只加「从模板铺」的源。
- **OS 直跑 go test/build 的机械验收**(engineering 的 build/test 型 run)仍留未来形态;10.4 OS 机械 accept 只读(允许清单);委派内 agent 自跑测试照旧。
- **凭据注入 / 主机 allowlist**:10.2 边界「凭据后移」+ 方向 §六 #2/#5(巡检只读凭据、主机 allowlist)未做。
- **不做合成计划编辑/改派 UI**:可审 = approve/reject(既有 Decide 语义);不满意 → reject 后改意图重跑;计划人工修编留后续。
- 非流水线手动任务 / workflow / split 子任务仍无 plan(GET plan null,10.3 边界)。
- 合成只服务 RunPipelineAs 建单的顶层流水线 run;子任务天然无 plan。
- 10.5+ 见方向 §八(例行模板数据化 / 高智合成模板补充 / 预算外部对接等)。

# Phase 3.1 — Research / Product Capability 就位 归档

> 阶段收口凭证。已冻结，只读。
> 关联设计：`docs/phase3/design/research-product.md` §4.1 / §6 / §9(3.1)。

## 一、目标与范围

- 目标：落地方向基线 Phase 3 的两个新 Capability——Research(Market / Technology / Competitor 调研)与 Product(Analyst / PRD / Roadmap),含 Agent 就位与按角色授予的最小权限策略。
- 范围：纯数据/CLI 层(capability / agent / policy / permission 表与命令 Phase 0 已建,复用),无代码改动、无迁移。
- 边界：Agent 仍为「命令即 description」执行(框架先行,不接真实 LLM/网络调研);跨 Capability Workflow 引擎在 3.2,端到端流程在 3.3。

## 二、交付物

| 交付物 | 验证方式 | 结果 |
|---|---|---|
| research Capability + 3 Agent(market/technology/competitor) | `os capability list` / `os agent list` 显示 | ✅ |
| product Capability + 3 Agent(analyst/prd/roadmap) | 同上 | ✅ |
| Agent 带 model_hint(复用 2.3 `--model`) | agent list 显示 claude-sonnet-5 | ✅ |
| 最小权限策略(research/product 角色可 read/write file) | policy/permission list 显示;授权角色写文件成功 | ✅ |
| 默认拒绝(未授权 role 调 shell) | task failed + audit deny | ✅ |

## 三、实现要点

- 无代码改动：capability / agent / policy / permission 均复用 Phase 0 命令;权限校验复用 Phase 1.4(按 agent.Role 匹配 permission.subject,默认拒绝)。
- 角色命名避免跨 Capability 撞名:engineering=architect/coding/qa/review,research=market/technology/competitor,product=analyst/prd/roadmap。当前授权仍按公司级 role 字符串(3.2 引入 capability 级解析后,语义由节点级 `capability` 字段收敛)。
- 产出物形态:research/product Agent 的产出(调研文档/PRD/路线图)是 workflow 节点 Task 在 workspace 内用 file-write 写入的文件(框架先行,内容由 description 提供)。

## 四、冒烟记录

环境:全新 DB `/tmp/opos-p3.db` + company `ACME`。

1. `os capability add --code research/product` → list 显示两行。
2. `os agent add --capability <rid> --role market/technology/competitor --model claude-sonnet-5` → research 3 Agent;同理 product 3 Agent。
3. `os policy add --kind allow`(research-file / product-file)+ 每角色 `permission add --subject <role> --action read|write --resource file` → policy list 2 行,permission 12 条。
4. 授权写:market Agent task(file-write `write research.md ...`)→ **completed**,`/tmp/opos-p3-ws-research/research.md 市场需求调研` 落盘。
5. 默认拒绝:market Agent task(shell `echo hack`)→ **failed** `unauthorized: role has no permission for execute/shell`,audit 记录 `tool/shell deny`(actor `agent:334d...`)。

注:`os task run` 对任务级失败返回 exit 0(任务结果非 CLI 错误),与 Phase 1/2 一致;deny 通过 task failed + audit 验证。

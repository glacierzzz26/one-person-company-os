# Phase 3.2 — 跨 Capability Workflow 引擎 归档

> 阶段收口凭证。已冻结，只读。
> 关联设计：`docs/phase3/design/research-product.md` §4.2 / §7 / §9(3.2)。

## 一、目标与范围

- 目标：把方向基线「Workflow 是跨 Capability 的流程编排」落地到执行引擎——workflow 节点可声明所属 capability，Agent 按 (capability, role) 解析，节点 Task 落 `capability_id`。
- 范围：`WorkflowNode` 加 `capability` 字段；新增 `resolveAgentForNode`(capability 分支解析 + 公司级回退)；sqlc 新增 `GetCapabilityByCode` / `GetAgentByCapabilityAndRole` 查询；节点 Task 透传 capability_id。无迁移、无 schema 变更(表列均已有)。
- 边界：审批门/轮询/失败中断等 2.2 逻辑不改；端到端产品开发流程在 3.3。

## 二、交付物

| 交付物 | 验证方式 | 结果 |
|---|---|---|
| `WorkflowNode.capability` 字段(JSON `capability,omitempty`) | definition 可声明；空字段节点仍工作 | ✅ |
| `resolveAgentForNode`：capability → (capability, role) 解析 | 混合 research/product/engineering workflow 正确解析 | ✅ |
| 节点 Task 落 `capability_id` | sqlite 查 3 个节点 Task 的 capability_id 各归其主 | ✅ |
| 错误中断：capability 不存在 / role 缺失 | `os workflow run` 在出错节点中断，exit=1 | ✅ |
| 向后兼容：无 capability 字段回退公司级 role | 旧 definition 运行成功 | ✅ |
| 示例 definition | `docs/phase3/examples/cross-capability-workflow.json` | ✅ |

## 三、实现要点

- **WorkflowNode**：新增 `Capability string \`json:"capability,omitempty"\``。非空 → 按 (company, code) 查 Capability，再按 (capability_id, role) 查 Agent；空 → 回退 2.2 的 `GetAgentByRole(company, role)`。
- **resolveAgentForNode(ctx, companyID, n) (agent.Agent, capabilityID, error)**：capability 分支返回 (agent, c.ID)；公司级回退返回 (agent, a.CapabilityID)——即使旧节点也把归属 Capability 落到 Task，语义自洽。
- **sqlc**：`capability.sql` 增 `GetCapabilityByCode(company_id, code)`；`agent.sql` 增 `GetAgentByCapabilityAndRole(capability_id, role)`。生成代码 + Store 方法同步。
- **Task 透传**：`runWorkflowNode` 把 capabilityID 传入 `CreateTask.TaskParams.CapabilityID`，`repository.CreateTask` 原有 `ptrToNull` 路径自动落库。
- **⚠️ 教训**：改动后只跑 `go build ./...`(仅编译)会导致 `bin/os` 还是旧二进制、capability_id 落库为 NULL 的假象；必须 `go build -o bin/os ./cmd/os` 重建运行件再冒烟。

## 四、冒烟记录

环境：3.1 的 `/tmp/opos-p3.db` + 补 engineering capability/architect agent。

1. 混合 workflow(3 节点:research→product→engineering,各带 capability)→ `3/3 nodes completed`;sqlite 查 Task:market→research、analyst→product、architect→engineering,capability_id 全部正确。
2. 错误 A:capability `nonexistent` → step 1 中断 `resolve capability "nonexistent": sql: no rows in result set`,exit=1。
3. 错误 B:capability `product` 下 role `nonexistent-role` → step 1 中断 `resolve agent for role ... in capability "product": sql: no rows`,exit=1。
4. 向后兼容:仅 `agent_role: architect`(无 capability)的节点 → completed,Task 落 engineering。

## 三、实现要点

- **token 只存密文**：`OS_ENDPOINT_KEY`(32-byte hex)缺失而带 token → 拒绝(fail-closed)；错 key → `cipher: message authentication failed`；空 token → 空串落库不加密(免 key 接入本地无鉴权端点)。明文永不出现在 token_enc / list / show。
- **厂商自动识别**：`anthropic.com` → vendor/proto `anthropic`，`openai.com` → `openai`；本地/未知域名默认 proto `auto`，`add` 可用 `--proto` 显式指定。
- **模型拉取**：单一 proto 只试对应请求头(anthropic：`x-api-key`+`anthropic-version:2023-06-01`；openai：`Authorization: Bearer`)；`auto` 先 anthropic 后 openai 双试。非 200 / 网络失败 / JSON 解析失败均清晰报错且**不写** models_cache；仅成功才缓存原始 body。
- **ClaudeCLI 凭据来源(实现期细化，见 §五)**：6.1 阶段 `ClaudeCLI.Generate` 凭据取自 config provider(`api_key_env` 指向的 shell env，`ANTHROPIC_AUTH_TOKEN`)，与 endpoint 行解耦——因 task→endpoint 关联列随 0008/6.2 才落；endpoint 解密 token 驱动 Generate 的绑定随 6.2 一起落地。`FetchEndpointModels` 的鉴权已直接走 endpoint 解密 token。
- **mock/real 切换**(按 §12 #1 倾向)：config provider `type: claude` → 真 claude CLI；其余(含 `stub`)→ Stub mock，无 key 冒烟沿用 stub。
- **零新依赖**：`net/http`、`crypto/aes-gcm`、`crypto/rand` 均标准库；uuid 复用既有依赖。

## 四、冒烟记录

环境：全新 DB `/tmp/opos61/os.db` + company ACME + `OS_ENDPOINT_KEY`(openssl rand -hex 32)。

1. 无 key 带 token `add` → 拒绝：`OS_ENDPOINT_KEY not set: required to encrypt endpoint token`(fail-closed)。
2. 空 token `add`(localhost)→ 成功，免 key。
3. 带 key `add` anthropic.com → 自动识别 `anthropic/anthropic`，token 密文落库。
4. 同 company 重名 `add` → `UNIQUE constraint failed: endpoint.company_id, endpoint.name (2067)`。
5. `endpoint list` 无 token 列；`endpoint show` → `TOKEN encrypted (aesgcm, 59 chars)`。
6. DB 直查：token_enc 为 `enc:v1:…`，明文 `sk-ant-test` 不在库内；空 token 行 token_enc 为空串。
7. 不可达端点 `models` → 清晰 transport 错误(`context deadline exceeded`)。
8. 本地假 `/v1/models`(openai)：拉取 parse 2 模型；models_cache 落 62 chars，show 显示 `62 chars (last /v1/models)`。
9. 假服务返回 `not-json` → `parse /v1/models response: invalid character…`，缓存不写入(length 0)。
10. 假 anthropic 端点要求 `x-api-key=sk-ant-test`：add 加密该 token，`models` 拉取成功 → 证明 **Seal→Open 解密往返可用**。
11. 换错 `OS_ENDPOINT_KEY` 再 `models` → `decrypt token: cipher: message authentication failed`。
12. `select --role bogus` → `--role must be pool|planner|standby (got "bogus")`；合法 select → model/role 更新，show 可见。

结论：本地可测机制全部符合设计。`接入 ≥2 异厂商端点 / os endpoint models 拉取非空 / 真实提问返回合法 JSON` 三项需真实 key 与可达端点，留用户验收(§五)。

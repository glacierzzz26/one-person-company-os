## 三、实现要点

- **回合状态落 task 行**(设计 §5.1)：`round_no`/`conflict_count` 由 driver 经 `SetTaskRound` 推进，overview/回放可读；不另建回合状态机。
- **回合机**：每轮开头 writer 产出 diff → test(失败→同轮免费返工，round/conflict 不动)→ review(approve→完成；needs_changes→conflict+1，<3 则 round+1 重写新轮，≥3 熔断)。测试免费返工上限 `engMaxFreeRework=3`，超限按不可恢复失败处理(防死循环)。
- **熔断续跑**：approve → 既有 `ApproveTask` requeue + `DecideApproval` 自动落 decision(kind=approval, source=approval:<id>)；下次认领 driver 见 `conflict_count≥3` → 视为人工已介入 → conflict 归零、round+1、`humanOverride=true` 重试。reject/changes → 既有 FailTask 语义。
- **家族分发不改语义**(设计 §11)：只在 `runClaimed` 顶部加 engineering 分支；0-5 全部 tool 路径(权限校验/approval/execution)逐字未动。
- **模型调用分界**：`engCall(role, round, conflict, humanOverride, retry, prompt)`。live = endpoint 行(base_url+selected_model+解密 token)构造 `ClaudeCLI`；无端点/token 解密失败 → fail-closed 清晰报错。`OS_ENGINE_MODE` 缺省 live(默认诚实，不静默降级)。
- **test/review 端点回退**(设计 §5.1“空 = agent 默认，先单端点跑通”)：test/review 优先 `reviewer_endpoint_id`，空则回退 `writer_endpoint_id`；writer 必须显式(单端点 = 两列填同一 id)。
- **实现期细化(归档裁定)**：设计 §6.2 字面“每回合 = 一条 execution”，为保阶段可回放，实现为**每阶段(写/测/审)各一条 execution**，结果带 `eng_<role> round=.. conflict=..` 前缀；`round_no`/`conflict_count` 在 task 行提供每回合汇总。
- **pre-repos 边界(归档裁定)**：6.2 三阶段均为模型调用 + 结构化解析(writer 产 diff 文本、test/qa 产 TEST 判定、review 产 VERDICT)。真实补丁应用/测试执行/仓库 workspace 是 6.3(0009 repos)的落地动作；diff 文本已在 execution/result 落库，供 6.3 消费。
- **scripted test double**(§12 #1 mock 保留)：`OS_SCRIPT_TEST`(pass/fail-once/fail-all)与 `OS_SCRIPT_REVIEW`(approve/reject/reject:N) 离线确定性驱动验收；仅冒烟/CI 用。

## 四、冒烟记录

环境：全新 DB `/tmp/opos62c/os.db` + company ACME62；engineering 任务经 `os task create --tool engineering`，`os task run` 执行。

1. **① 写→测过→审过→完成**：completed，round=0 conflict=0；executions = writer/test/review 各 1。
2. **② review 驳回→同任务返工→通过**(`OS_SCRIPT_REVIEW=reject:1`)：completed，round=1 conflict=1；executions 序列 writer r0→test r0→review r0(needs_changes)→writer r1→test r1→review r1(approve)。验证冲突累计与跨轮重写。
3. **③ 达 3 轮熔断 + approve 续跑 + decision 自动落库**(`OS_SCRIPT_REVIEW=reject:3`)：
   - run1 → `waiting_approval`，round=2 conflict=3；pending approval reason=`engineering fuse: reviewer rejected 3 times`。
   - `os approval approve` → task requeue；decision 落库 `审批 approved: fuse`(kind=approval, source=approval:<id>)。
   - run2(续跑)→ completed，round=3 conflict=0(conflict 归零、humanOverride 放行)。
4. **④ 测试失败→免费返工**(`OS_SCRIPT_TEST=fail-once`)：completed，round=0 conflict=0(不累计)；executions = writer×2(test FAIL 后同轮重写 retry1)、test×2(FAIL→OK)、review。
5. **⑤ live 缺省 fail-closed**：engineering 任务不挂端点直接 run → failed，LastError=`no writer endpoint set (use --writer-endpoint/--reviewer-endpoint, or OS_ENGINE_MODE=scripted...)`。

结论：本地可测机制全部符合设计 §10(6.2) 验收；`真实 bugfix 任务`(live，真实端点/真实 claude)由用户验收(§五)。

## 五、已知问题 / 待办

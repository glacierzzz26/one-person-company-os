# Phase 0 — Company Kernel 归档

> 阶段收口凭证。已冻结，只读。

## 一、目标与范围

- 目标：建立"公司操作系统"核心模型地基——Company / Capability / Agent / Policy / Permission / Workflow / Task / Audit 的领域定义与持久化，通过 CLI 可创建与读取。
- 范围：Go 骨架、SQLite 存储（SQLC + 迁移）、领域层、repository 层、service 层（写操作自动落 Audit）、Cobra CLI。
- 边界：不做 Queue / Workflow 引擎编排 / Agent Runtime / Tool / Sandbox / Approval 流程（Phase 1）；Task 状态固定 pending；Permission 只存不校验；不做 Memory/Decision 实体。

## 三、实现要点

- **无 CGO 构建**：SQLite 驱动用 `modernc.org/sqlite`（纯 Go）。迁移采用自研轻量 runner（`internal/storage/migrate.go`）——方向基线选型为 golang-migrate，但其 SQLite driver 依赖 CGO；为保持纯 Go 构建，Phase 0 偏差记录在此，后续可切回。
- **分层**：`Domain (internal/<entity>) → Repository 接口 (internal/storage/repository) → SQLC (internal/storage/query) → SQLite`，符合方向基线"上层 Domain 不感知数据库类型"。
- **写操作统一过 service**：`internal/service` 的每个 create 方法自动落一条 Audit（actor=`human:cli`）。
- **Task 状态**：创建固定 `pending`（v1.1 决策）；`capability_id/workflow_id/agent_id` 可空，repository 层 `*string ↔ sql.NullString` 转换。
- **幂等/一致性**：SQLite 单写者，`SetMaxOpenConns(1)`；`PRAGMA foreign_keys=ON`。
- **数据血缘**：所有展示字段直接来自对应表；审计 `entity_id` 指向实体主键。

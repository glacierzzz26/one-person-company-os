# Phase 2.1 — Engineering Tools 归档

> 阶段收口凭证。已冻结，只读。
> 关联设计：`docs/phase2/design/engineering-capability.md` §3 / §6 / §9 / §10。

## 一、目标与范围

- 目标：建立 Engineering 业务能力域的第一批工具——git / file。Tool 走 Phase 1.2 接口 + Registry，权限校验、Audit 自动生效；在宿主 workspace 内操作真实文件与本地仓库。
- 范围：task 增加 `tool_name` 字段（引擎按名取 Tool，取消硬编码 shell）、git Tool（本地子命令白名单）、file-read / file-write Tool（最小权限拆分 + workspace 边界强制）、CLI `os task create --tool`。
- 边界：8 阶段 Workflow（2.2）、4 Agent + Model Provider 接入（2.3）不做；不改执行引擎内部机制（Phase 1.1-1.4 冻结）；git 网络操作本阶段明确拒绝（后续 + 审批）。

## 三、实现要点

- **tool_name 字段**（设计 §4.3 定稿后澄清）：`task.tool_name TEXT NOT NULL DEFAULT 'shell'`（迁移 0004）；CreateTask/ClaimTask/CompleteTask 等全部 task 查询经 sqlc 重新生成带 tool_name。`execution.go runClaimed` 由 `tool.Get("shell")` 改为 `tool.Get(t.ToolName)`，未注册时给出含 task id 的明确错误。`WorkflowNode` 增加 `tool` 字段（JSON），workflow definition 已可指定节点 Tool。
- **git Tool**（宿主执行）：`exec.Command("git", "-C", <workspace>, ...)`，绕过 Docker 无网络限制。本地子命令白名单（init/status/add/rm/mv/commit/diff/log/show/branch/config/rev-parse/tag/grep），网络子命令（clone/pull/push/fetch/remote/ls-remote/submodule）显式拒绝并返回设计口径错误。命令解析自 task.Description，支持引号/转义（`splitArgs`），兼容 `git <sub> ...` 与裸 `<sub> ...` 两种写法。
- **file-read / file-write**（宿主执行）：按最小权限拆为两个 Tool——读角色（review）只需 read/file，写角色（coding）才需 write/file；Tool 接口 Permission 为单 action/resource，无法在单 Tool 内表达 read+write。命令格式 `write <path>\n<content>` / `read <path>`。
- **workspace 边界强制**：`resolveWorkspacePath` 三重校验——拒绝空路径、拒绝绝对路径、`filepath.Clean` + `filepath.Rel` 双重检查防 `../` 穿越（含 `sub/../../` 嵌套形式）。
- **CLI**：`os task create --tool <name>`（默认 shell）；`os tool list` 展示 4 个 Tool（shell/git/file-read/file-write）。
- **权限复用**（Phase 1.4 机制）：`authorizeTool` 按 task.agent_id 的 role 匹配 enabled allow policy 的 subject/action/resource；无 Agent 或未命中 → 默认拒绝 + Audit deny。

## 四、冒烟记录

环境：全新 DB + engineering capability + coding/review/architect 三 agent + allow policy（coding: write/file, read/file, execute/git；review: read/file）。workspace 宿主路径 `/tmp/os-smoke-21/ws`。

1. `os task create --tool file-write ... 'write README.md\nhello from phase 2.1'` → run → **completed**，宿主磁盘生成 README.md（20 bytes）。
2. `os task create --tool file-read ... 'read README.md'` → run → **completed**，返回内容一致。
3. `read ../secret.txt` → **failed**「path "../secret.txt" escapes workspace」。
4. `read /etc/hostname` → **failed**「absolute path not allowed」。
5. `read sub/../../secret.txt` → **failed**「escapes workspace」。
6. git 序列 `init` / `config user.name agent` / `config user.email agent@local` / `add README.md` / `commit -m "initial commit"` / `log --oneline` / `status` → 全部 **completed**，`b0f6265 initial commit`、working tree clean。
7. `git pull origin main` → **failed**「network operation, not supported in Phase 2.1」。
8. architect（无权限）调 file-write → **failed**「unauthorized: role has no permission for write/file」+ audit `tool/file-write deny`。
9. `--tool bogus` → run 报错「task ... tool "bogus" not registered」。
10. `os audit list` / `os execution list`：每次调用均有 execution start/complete（或 fail）+ 对应 audit；未授权有 tool deny。

## 五、已知问题 / 待办

- [ ] git 网络子命令（clone/pull/push/fetch）仅返回「不支持」，未走审批放行路径——设计约定「后续 + 审批」。
- [ ] `--cpus/--memory/镜像` 硬编码于 ShellTool（承 1.2）；git/file 宿主执行依赖宿主机已安装 git，未探测/降级。
- [ ] `os task show / list` 暂不展示 tool_name（不在 §10 CLI 契约内；需要时补列即可）。
- [ ] 成功 Tool 调用经 execution 记录落审计（entity=execution start/complete），未单列 entity=tool 的 allow 记录——与 Phase 1 一致，符合「不改执行引擎」边界。
- [ ] git 命令解析用自研 `splitArgs`（支持引号/转义），未引入 shell-quote 库；覆盖常见场景，极端转义未穷举。

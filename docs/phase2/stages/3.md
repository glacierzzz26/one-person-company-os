## 一、目标与范围

- 目标：建立 Engineering 8 阶段流程（Issue→Analysis→Plan→Implementation→Test→Review→Approval→Delivery），复用 Phase 1 引擎在真实仓库上一键运行，审批门人工决定续跑/中断，节点失败中断。
- 范围：8 阶段 workflow 定义（`docs/phase2/examples/engineering-workflow.json`）、RunWorkflow 增加审批门暂停/续跑与 skip 输入节点、`os workflow run` 进度输出。
- 边界：4 Agent + Model Provider 接入（2.3）不做；不改底层机制（Task 状态机 / 队列 / 审批 / 权限校验，1.1-1.4 冻结），只扩展 workflow 编排层的「审批门」语义。

## 三、实现要点

- **WorkflowNode 扩展**：`skip bool`（输入声明节点，如 issue：不创建/不执行 Task，只留审计）。agent_role 为空且非 skip 的节点 = **审批门**：无实际执行内容，进入等待审批，人工 approve 后引擎直接置 completed 放行。
- **RunWorkflow 审批门语义**（`driveTaskToCompletion`）：节点 Task 状态机驱动循环——
  - `pending` → `ExecuteTask`（首次创建即执行）；
  - `waiting_approval` → 审计 `pause` 并轮询（1s，ctx 可中断）等待人工决定；
  - approve 后 Task 回 `pending`：审批门直接 `CompleteTask("approved by human")`；执行节点重跑一次（`HasApprovedApproval` 使其放行，不再触发审批）；
  - reject/changes → Task `failed` → 返回错误中断整个 workflow（后续节点不创建）。
- **复用 Phase 1 机制不变**：审批触发（risk=high）、waiting_approval 流转、approve/reject/changes、Tool 权限校验（默认拒绝）、Execution/Audit 落库均为 1.4 既有实现；本阶段只把 workflow 编排从「fail-fast」扩展为「审批门暂停 + 续跑」。
- **共享 workspace**：8 节点显式指向同一仓库路径（定义中 `workspace` 全节点一致），保证文件在 analysis→delivery 间连续；仓库需预先 git init 并跟踪交付文件（delivery 用 `git commit -am` 提交已跟踪文件的变更）。`<repo-workspace>` 为环境相关占位符，运行前替换为目标仓库路径。
- **CLI**：`os workflow run <id>` 增加进度输出（`→ step (tool): title`、`⏸ step: waiting approval on task ... (os approval list / approve <id>)`），结束打印 `N/M nodes completed` 摘要。
- **Issue 输入建模**：issue 节点 `skip:true`，title/description 承载需求文本；需求即 workflow 上下文，不作为 Task 执行（与「起始节点不作执行」一致）。

## 四、冒烟记录

环境：全新 DB + engineering capability + architect/coding/qa/review 四 agent + allow policy（architect: write/file；coding: write/file, execute/git；qa: execute/shell；review: read/file）。真实 git 仓库 `/tmp/os-smoke-22/repo`（预置跟踪 greeting.txt + 1 个 commit）。

1. `os workflow run` 一键运行：issue skip → analysis/plan（file-write 产出 ANALYSIS.md/PLAN.md）→ implementation（file-write 覆盖 greeting.txt 为新问候语）→ test（shell `grep` 校验 PASS）→ review（file-read）→ approval 门暂停。
2. `os approval approve` 放行审批门 → 进入 delivery（high）→ 再次暂停。
3. `os approval approve` 放行 delivery → `git commit -am "deliver greeting"` 执行 → `7/7 nodes completed`，仓库新增 commit `cf47751`。
4. 重跑 → 审批门 reject → `Error: workflow Engineering aborted at step approval ... rejected by human`，delivery 未创建。
5. 3 节点 workflow（analysis ok / test `exit 1` / review）→ aborted at step test，review 未创建。
6. audit 核对：workflow skip/pause×2/run(7/7) + approval×2 记录齐全。

## 五、已知问题 / 待办

- [ ] 审批门与 high-risk 执行节点是**两次**独立审批（approval 门 + delivery 各一次）；如需「一次审批覆盖交付」可合并节点或引入审批 scope，留待后续。
- [ ] `os workflow run` 在审批门处**阻塞**等待人工决定（前台 CLI 语义）；headless 场景无超时，靠 Ctrl+C 中断。
- [ ] workflow 无独立 WorkflowRun 实体/进度视图（承 1.3 已知问题）；暂停位靠任务状态 + audit pause 记录体现。
- [ ] 共享 workspace 靠定义中显式重复路径实现；后续可演进为 run 级共享 workspace。
- [ ] 节点仍为「命令即 description」框架先行语义；LLM Agent 编排（选择 Tool/生成命令）属 2.3。

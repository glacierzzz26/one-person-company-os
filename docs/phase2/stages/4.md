## 三、实现要点

- **Provider 抽象**：`Provider` 接口 = `Name/Type/Model/Endpoint`（来自 config 声明）+ `Generate(ctx, Request) (Response, error)`；`Stub` 实现返回 mock 内容 `[mock <type>/<model>] <prompt>`。方向基线「Agent → Runtime → Model」框架就位，真实 provider（Anthropic/OpenAI 等）后续按同一接口落地。
- **config providers**：`Config.Providers []Provider`（yaml `providers:`，字段 name/type/model/endpoint/api_key_env）。api_key_env 指示真实接入时密钥所在环境变量名（本阶段为空/占位，不读取）。
- **Agent 关联**：`os agent add --model <model>` 落库 `agent.model_hint`（表列 Phase 0 已建）；`os agent list` 展示。本阶段 model_hint 仅信息性——Agent↔Provider 绑定/解析留待真实接入。
- **aifix Tool**：标准 Tool 接口（Permission execute/aifix、Risk low、Input/Output Schema）；`Execute` mock 实现：以 task.Description 为问题，返回模拟修复方案文本。契约与真实接入端点约定见 design §8。
- **CLI**：`os provider list` 独立于 svc（仅读 config）；`os tool list` 自动纳入 aifix（init 注册）。

## 四、冒烟记录

环境：全新 DB + engineering capability + qa agent（--model claude-sonnet-5）+ allow policy（qa: execute/aifix）。

1. `os provider list` → `local-mock`(stub/mock-1) + `anthropic-stub`(stub/claude-sonnet-5, ANTHROPIC_API_KEY) 两行。
2. `os agent add --capability ... --role qa --model claude-sonnet-5` → `os agent list` 显示 MODEL=claude-sonnet-5。
3. `os tool list` → aifix（low / execute/aifix）在列。
4. `os task create --tool aifix --description "登录超时偶发 500"` → `os task run` → **completed**，结果 `[mock fix] 对问题 "登录超时偶发 500" 生成修复方案(真实 AI-Fix 待接入,见 §8)`。
5. 权限默认拒绝链路复用 2.1（未授权 role 调 aifix → 拒绝 + audit deny）——未单独重测。

## 五、已知问题 / 待办

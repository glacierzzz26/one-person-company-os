# Phase 5.3 — 全景运营视图 归档

> 阶段收口凭证。已冻结，只读。
> 关联设计：`docs/phase5/design/oneperson-os.md` §6 / §8(5.3)。

## 一、目标与范围

- 目标：一人操作台——`os overview` 单命令聚合全公司状态,把注意力导向「真正需要人决策的事项」(待审批)。
- 范围：service 层只读聚合 + 2 个聚合查询(task.sql)+ CLI。无新表、无迁移。
- 边界：前端/Dashboard 独立排期(设计 §2);overview 只读,不落 audit(纯查询)。

## 二、交付物

| 交付物 | 验证方式 | 结果 |
|---|---|---|
| `os overview --company` 7 区块 | Company / Capabilities / Workflows / Pending Approvals / Recent Decisions / Recent Tasks / Memory Highlights 全部展示 | ✅ |
| Workflow 任务状态计数 | 运行后 failed=1 正确显示 | ✅ |
| 待审批醒目 | high-risk task 停到 waiting_approval → Pending Approvals 区块列出(approval id/task/risk/title/reason) | ✅ |
| 只读聚合,无新表 | overview 复用现有 repository;git status 无迁移文件 | ✅ |

## 三、实现要点

- **聚合查询**：新增 `ListRecentTasks`(company, limit, 创建倒序)与 `TaskStatusCountsByWorkflow`(GROUP BY workflow_id, status)。其余区块复用现有 List* repository 方法。
- **服务层聚合**：`service.Overview` 组装 `Overview` 结构;capability×agent 数、approval+task 标题 join、decision/memory 截断取近 N 条。
- **CLI 展示**：区块标题 + 文本表格;Pending Approvals 区块标题注明「需要你决策」。
- **零副作用**：纯只读,不产生 audit(与 5.1/5.2 写路径区分)。

## 四、冒烟记录

环境：`/tmp/opos-p5.db` ACME(5.1/5.2 数据 + 补 marketing capability 2 Agent + 2 workflow)。

1. `os overview` → Company(vision)、Capabilities(marketing 2 agents)、Workflows(2 个)、Recent Decisions(5 条)、Recent Tasks、Memory Highlights(3 条)全展示。
2. 建 workflow(p5-overview-wf2)含 shell 节点 → run 因无权限 failed → overview Workflows 块显示 `failed=1`(状态计数正确)。
3. 建 high-risk task → run → waiting_approval → overview Pending Approvals 块列出该审批(approval a8ef12de / risk=high / 标题 / reason=risk=high)。

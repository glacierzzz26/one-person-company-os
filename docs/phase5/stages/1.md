## 三、实现要点

- **FTS5 分词器 trigram + LIKE 兜底**：unicode61 对 CJK 连续字符不切分(「反馈」搜不到「客户反馈」)。改用 **trigram**(≥3 字符中英文子串匹配)+ **双字短查询(<3 runes)走 LIKE 子串**兜底,覆盖全部搜索场景。
- **FTS5 独立索引表 + 触发器**：`memory_fts(memory_id, title, content)` 由 INSERT/DELETE/UPDATE 触发器同步(SQLite 标准外部内容模式);search 时 join 回 memory 取完整行。
- **search 走原 SQL**：FTS5 MATCH 参数化查询不经 sqlc(避免 sqlc 解析 VIRTUAL TABLE);CRUD 走 sqlc 生成。
- **source 字段是数据血缘**：每条知识知道来源(workflow:<id>/task:<id>/approval:<id>/manual),为 5.4 流程沉淀铺路。

## 四、冒烟记录

环境：全新 DB `/tmp/opos-p5.db` + company `ACME`。

1. `os memory add` 3 条(lesson 客户反馈处理教训 / knowledge 定价基线 / convention 发布约定)→ `os memory list` 3 行,`--type lesson` 过滤 1 行。
2. `os memory search` 用例:
   - `workflow`(英文,FTS)→ 命中 lesson
   - `审批门`(3 字,trigram)→ 命中 convention
   - `反馈` / `审批` / `定价` / `小时`(2 字,LIKE 兜底)→ 各命中正确条目
   - `客户`(2 字,LIKE)→ 命中 lesson+knowledge(两者含「客户」)
   - `不存在的词` → 空(无匹配)
3. `os audit list --entity-type memory` → 3 条 create,actor `human:cli`,detail 为 type。

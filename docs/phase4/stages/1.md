# Phase 4.1 — Marketing / Sales Capability 就位 归档

> 阶段收口凭证。已冻结，只读。
> 关联设计：`docs/phase4/design/business-capabilities.md` §4 / §7 / §9(4.1)。

## 一、目标与范围

- 目标：落地方向基线 Phase 4 的前两个 Business Capability——Marketing(campaign / content / seo)与 Sales(lead / proposal / account),含 Agent 就位与最小权限策略。
- 范围：纯数据/CLI 层(capability / agent / policy / permission 复用 Phase 0 命令),无代码改动、无迁移。
- 边界：Business Agent 仍「命令即 description」执行(框架先行,不接真实 CRM/LLM);其余三个 Capability 在 4.2,端到端流程在 4.3。

## 二、交付物

| 交付物 | 验证方式 | 结果 |
|---|---|---|
| marketing Capability + 3 Agent(campaign/content/seo) | `os capability/agent list` 显示 | ✅ |
| sales Capability + 3 Agent(lead/proposal/account) | 同上 | ✅ |
| Agent 带 model_hint(复用 2.3 `--model`) | agent list 显示 claude-sonnet-5 | ✅ |
| 最小权限策略(marketing/sales 各角色 read/write file) | policy list 2 行;授权角色写文件成功 | ✅ |
| 默认拒绝(未授权 role 调 shell) | task failed + audit deny | ✅ |

## 三、实现要点

- 无代码改动:Capability / Agent / Policy / Permission 全部复用现有命令;权限校验复用 Phase 1.4(按 agent.Role 匹配 permission.subject,默认拒绝)。
- 角色命名避免跨 Capability 撞名(3.2 约定延续):engineering=architect/coding/qa/review,research=market/technology/competitor,product=analyst/prd/roadmap,marketing=campaign/content/seo,sales=lead/proposal/account。
- 产出物形态:Business 产出(营销计划/文案等)为 workflow 节点 Task 在 workspace 用 file-write 写入的文档。

## 四、冒烟记录

环境:全新 DB `/tmp/opos-p4.db` + company `ACME`。

1. `os capability add --code marketing/sales` → list 两行。
2. `os agent add`(6 Agent,各 `--model claude-sonnet-5`)→ agent list 各 3 行。
3. `os policy add --kind allow`(marketing-file / sales-file)+ 每角色 `permission add read|write file` → policy 2 行。
4. 授权写:campaign task(file-write `write campaign.md ...`)→ **completed**,`/tmp/opos-p4-ws-mkt/campaign.md 季度营销计划` 落盘。
5. 默认拒绝:campaign task(shell `echo x`)→ **failed** `unauthorized: role has no permission for execute/shell`,audit `tool/shell deny`(actor `agent:f608...`)。

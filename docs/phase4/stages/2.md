# Phase 4.2 — Customer / Operations / Finance Capability 就位 归档

> 阶段收口凭证。已冻结，只读。
> 关联设计：`docs/phase4/design/business-capabilities.md` §4 / §7 / §9(4.2)。

## 一、目标与范围

- 目标：补齐方向基线 Phase 4 的后三个 Business Capability——Customer(support / onboarding)、Operations(process / quality)、Finance(bookkeeping / reporting),与 4.1 的 Marketing / Sales 一起形成完整的 5 个 Business Capability。
- 范围：纯数据/CLI 层(复用现有命令),无代码改动、无迁移。
- 边界：Business Agent 仍「命令即 description」执行(框架先行);端到端跨 Capability 业务流程在 4.3。

## 二、交付物

| 交付物 | 验证方式 | 结果 |
|---|---|---|
| customer Capability + 2 Agent(support/onboarding) | `os capability/agent list` 显示 | ✅ |
| operations Capability + 2 Agent(process/quality) | 同上 | ✅ |
| finance Capability + 2 Agent(bookkeeping/reporting) | 同上 | ✅ |
| 5 个 Business Capability 齐(含 4.1 marketing/sales) | `os capability list` 5 行 | ✅ |
| 最小权限策略(3 新 Capability 各角色 read/write file) | policy list 5 行(含 4.1) | ✅ |
| 默认拒绝(未授权 role 调 shell) | task failed + audit deny | ✅ |

## 三、实现要点

- 无代码改动:完全复用现有 CLI 与引擎;跨 Capability 归属由 3.2 的 (capability, role) 机制保证。
- 角色命名继续避免撞名(3.2 约定):marketing=campaign/content/seo,sales=lead/proposal/account,customer=support/onboarding,operations=process/quality,finance=bookkeeping/reporting。
- 每个 Capability 独立 policy(customer-file / ops-file / finance-file),最小权限。

## 四、冒烟记录

环境:4.1 的 `/tmp/opos-p4.db`(company `ACME`)。

1. `os capability add --code customer/operations/finance` → capability list 5 行(marketing/sales/customer/operations/finance)。
2. `os agent add`(6 Agent,各 `--model claude-sonnet-5`)→ 每 Capability 2 Agent。
3. `os policy add --kind allow` + 每角色 `permission add read|write file` → policy 5 行。
4. 授权写:support 写 `support.md`、reporting 写 `report.md` → 均 completed,文件落盘 `/tmp/opos-p4-ws-biz/`。
5. 默认拒绝:reporting task(shell)→ **failed** `unauthorized: role has no permission for execute/shell`。

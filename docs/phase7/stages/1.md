# Phase 7.1 — 运营控制台 JSON API(数据通道先行)归档

> 阶段收口凭证。已冻结,只读。
> 关联设计:`docs/phase7/design/web-console.md` §五 端点契约 / §九 验收。

## 一、目标与范围

- 目标(设计 §一/§九):CLI `os overview` 是唯一全景入口且只面向本地终端——先给「一人操作台」补一条
  `/api/v1` JSON 读/写数据通道(overview/组织/任务/审批/决策/记忆/审计/模型端点池/通道 B 仓库账本),
  全部复用 Phase 0–6 的 `service` 方法(单一事实源,零语义改动);UI 后置到 7.2(React+TS+AntD)。
- 范围:域结构体补 `json` snake_case tag(返回原样序列化)+ `internal/server/api.go`(信封 helper + bearer
  中间件 + 各域 thin-wrapper handler)+ `Handler()` 挂 `/api/v1` 组 + CLI `os server` 读 `OS_API_TOKEN`。
- 边界:**无新迁移、无 sqlc 改动、无新 go.mod 依赖**(chi v5.2.5 已在);无 UI/分页/CORS/多用户;
  `task run / queue work / workflow run` 不暴露(长时阻塞,驱动留 CLI 与后台轮询,契约标 ❌)。

## 三、实现要点

- **tag = 单一事实源**:契约字段形状 = 域模型字段。给 `company/capability/agent/workflow/task/approval/
  decision/memory/audit/endpoint/repo/execution` model + `service.Overview/CapabilityView/WorkflowView/
  ApprovalView/RDOverview/RDTask` + `service.IntakeResult/intakeAsk` 补 `json:"snake_case"`;
  CLI 用 fmt 输出,不受影响。可选指针(如 `task.capability_id`)无 omitempty → 诚实 `null`。
- **thin wrapper 直调 svc**:handler 复用既有 `writeJSON`;错误统一 `handleServiceErr`
  (`errors.Is(sql.ErrNoRows)` → 404;存储层 sqlc 原样返回可判定)。写端点请求体小 struct 内联,
  缺必填(对齐 CLI 语义:decision 需 company/kind/title,status 默认 made;memory 需 company/type/title;
  endpoint 需 company/name/base_url,proto 默认 auto)在 handler 校验 → 400,避免落 500。
- **认证不靠改绑 localhost**:`os server` 因收 GitHub webhook 必须公网可达 → `/api/v1` 组挂可选 bearer
  (`OS_API_TOKEN` env,subtle.ConstantTimeCompare);未设 = 开放(单算子本地姿态,启动日志与文档标注风险)。
  token/secret 不入 JSON 响应与日志。
- **决策写与 CLI 同语义**:`POST /api/v1/approvals/{id}/decision` → `DecideApproval`(approve→任务回队
  pending/ready,reject/changes→failed 带备注;自动落 kind=approval decision,Source=approval:<id>)。

## 四、冒烟记录

环境:全新 DB + engineering capability + `OS_ENGINE_MODE=scripted` + `OS_ISSUE_SOURCE=fixture`(离线全确定性);
CLI seed(公司/工程 Capability/coding Agent + approve 完成 1 条 + reject×3 熔断 1 条)→ 后台 `os server`
无 token(:8791)与 `OS_API_TOKEN=sek`(:8792)两起,curl + jq 断言 **24 项全 PASS**:

1. **A 基础/组织读**:healthz ok;`GET /companies` 见 ACME;`GET /companies/<id>/overview` RD 块存在且
   `fused[0]`=flaky auth refactor conflict=3(`rd`/`capability_id`/`subtask_count`/`ledger`/`ledger_seen` 键在)。✅
2. **B 审批写**:`GET /approvals?status=pending` 含 reason `engineering fuse` 项;
   `POST /approvals/{id}/decision {approve}` → `approval.status=approved`;`overview.rd.fused` 清空;
   `GET /decisions?kind=approval` ≥1(自动落库)。✅
3. **C 记忆**:`POST /memories` 201;`GET /memories/search?q=审批门`(≥3 字 FTS)返回 1 条。✅
4. **D 通道 B**:`POST /companies/<id>/repos` + `POST /companies/<id>/intake/sync`(fixture #101)→
   `issues_seen=1, by_disp.direct_work=1`;overview `rd.ledger.direct_work=1, ledger_seen=1`。✅
5. **E 错误映射**:不存在 task → 404 not_found;POST task 缺 title → 400 bad_request。✅
6. **F 认证**:无 token 起(:8792,OS_API_TOKEN=sek):`GET /api/v1/*` 无头 401 / `Authorization: Bearer sek`
   200;`/healthz` 免认证 200。✅

`go build -o bin/os ./cmd/os` 通过;`go test ./...` 全绿(新增 internal/server api_test 5 例)。

结论:控制台数据通道落地——浏览器/手机/脚本可经同一 service 面读全景(含 RD 研发部块)并做核心人工决策
(审批/建任务/记决策/沉淀记忆/配端点仓库/触发 intake),JSON 契约冻结(design web-console.md §五)。

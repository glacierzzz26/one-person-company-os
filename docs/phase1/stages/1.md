# Phase 1.1 — Execution Core 归档

> 阶段收口凭证。已冻结，只读。

## 一、目标与范围

- 目标：让 Task 真正"动起来"——SQLite-backed Queue 消费任务，状态机流转，Execution 落库，支持重试/超时/租约/恢复。
- 范围（设计文档 `docs/phase1/design/execution-kernel.md` 子阶段 1.1）：Task Queue、Task 状态机、Execution 实体、Worker 循环、Runtime 接口、CLI（`os queue work` / `os task run` / `os execution list,show`）。
- 边界：Tool / Workspace / Docker Sandbox（1.2）、Workflow Engine（1.3）、Approval / Permission 校验（1.4）不做；Task 状态机的 `waiting_approval` 分支留待 1.4。

## 三、实现要点

- **双状态字段**：`task.status`（业务态 pending/running/completed/failed，1.4 加 waiting_approval）与 `task.qstatus`（队列态 ready/leased/running/completed/failed）分离——后者承载租约与恢复，前者承载用户可见语义。
- **原子领取**：`UPDATE task SET qstatus='leased' ... WHERE id=(SELECT ... ORDER BY priority DESC LIMIT 1) RETURNING *`，配合 `SetMaxOpenConns(1)` + `PRAGMA busy_timeout=5000`，多 worker 进程不重复领取。
- **重试语义**：`attempt` 从 0 起；失败且 `attempt < max_attempts-1` → Requeue（attempt+1 回 READY），否则终态 FAILED。
- **租约/恢复**：领取时写 `lease_until`（默认 30min）；worker 启动时把 `qstatus='leased' AND lease_until < now` 的孤儿回收为 READY。未实现执行中续期（见已知问题）。
- **Runtime 可替换**：`internal/runtime` 接口 + Registry（按名字取），Shell 实现注册为 "shell"。方向基线"架构允许替换"已满足，1.2 增 Tool 时复用同一注册模式。
- **Phase 1.1 Shell Runtime 语义**：无 LLM Agent 前，Runtime 在 Task 工作区目录执行 `task.Description` 作为命令（`sh -c`），超时受 ctx 控制。

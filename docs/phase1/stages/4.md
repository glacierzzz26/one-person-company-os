# Phase 1.4 — Approval + Permission 校验 归档

> 阶段收口凭证。已冻结，只读。Phase 1（Execution Kernel）至此全部完成。

## 一、目标与范围

- 目标：把治理链接入执行路径——high-risk 或命中审批规则的 Task 进入人工审批，未经批准不执行；Tool 调用前权限校验生效。
- 范围（设计文档 `docs/phase1/design/execution-kernel.md` 子阶段 1.4 + 第 9 节）：Approval 实体、审批触发判定、waiting_approval 状态流转、`os approval list/show/approve/reject/changes`、权限校验与核心约束。
- 边界：具体业务 Agent 与模型接入（Phase 2）、跨 Capability 编排（Phase 3）不做。

## 二、交付物

| 交付物 | 验证方式 | 结果 |
|---|---|---|
| high-risk Task → waiting_approval，不执行 | smoke：high-risk task run 后 status=waiting_approval，execution 无记录 | ✅ |
| approve 放行 → 重新入队 → worker 完成 | smoke：approve 后 queue work → completed | ✅ |
| reject → Task failed | smoke：reject 后 status=failed，last_error=rejected by human | ✅ |
| changes → Task failed + 备注 | smoke：changes --note → last_error 含备注 | ✅ |
| 审批规则命中 policy（kind=approval） | smoke：enabled approval policy 使 low-risk task 也触发审批 | ✅ |
| Tool 调用前 permission 校验 | smoke：无权限 role 的 task failed + audit deny | ✅ |

## 三、实现要点

- **审批触发判定**（`service.needsApproval`）：已有人工批准记录（`approval.status='approved'`）→ 放行不再触发（避免 approve 后重入队再被拦截的死循环）；否则 `risk=high`，或公司存在 enabled `kind='approval'` policy（statement 作 reason）→ 触发。
- **waiting_approval 流转**：触发时创建 Approval 记录（pending），Task 置 `status='waiting_approval'`、`qstatus='waiting_approval'`（新增队列态，释放租约、不再入队、不被 worker 领取/recovery）。执行路径 `runClaimed` 领取后先查审批，再走 Tool 权限校验。
- **人工决定**（`service.DecideApproval`，actor 固定 `human:cli`，Agent 路径无法触碰）：approve → Task 重新入队（qstatus=ready/pending）；reject / changes → Task failed（reject=rejected by human，changes 带备注）。Approval 状态：pending→approved / rejected / changes，写 decided_by/decided_at。
- **Permission 校验**：1.2 已实现 Tool 调用前按 role 校验（默认拒绝 + Audit deny），1.4 起作为治理链正式环节；核心约束（改 Policy/Permission/删 Audit/绕过 Approval）只经受控 CLI 命令触达，不暴露给 Tool/Runtime 通用通道。
- **迁移 0003**：`approval` 表（task_id/risk/reason/status/requested_by/decided_by/decision_note/created_at/decided_at）+ `idx_approval_task`。
- **CLI**：`os approval list [--status]`（列表显示完整 id 以便回填决策）/ `show` / `approve|reject|changes <id> [--note]`；`os policy add` 校验放宽至 `allow | deny | approval`。

## 四、已知问题 / 待办

- [ ] Approval 无单独"审批流/多级审批"，单次人工决定即终态（方向基线允许后续扩展）。
- [ ] `changes` 语义为"打回并置 failed"（带备注），"修改后重试"需人工重新创建 Task，未做自动再入队。
- [ ] policy 审批规则为"存在 enabled approval policy 即整公司触发"的粗粒度；按 action/resource 的细粒度规则（permission 挂 approval policy）留待后续。
- [ ] 无后台常驻 worker 与心跳续租（承 1.1）：长任务租约可能被误回收。
- [ ] Sandbox 资源参数（--cpus/--memory/镜像）硬编码于 ShellTool（承 1.2）。

## 一、定位与目标

现状里,要「多一个例行活 / 一种工作形态」时,理解上总归要动 Go(新判读解析、新执行原语、新外部触点),
或至少人肉铺 JSON 步骤。用户要把它推到底:**加一条流水线 = 在页面上写一段意图 + 护栏,落库即生效,不改代码**;
而跑起来后,由**高智模型当运行时架构师**——对着意图 + 可用资源现场拆阶段、订每阶段的输入/输出契约与分配,
OS 逐阶段验收执行。

同时给所有「项目的事」一个**物理容器**:一个项目一个目录(code、knowledge 等类型化子目录都收在下面),
这个项目绑定的所有流水线(不管 bugfix / 开发 / 运维)只能在这个目录内工作——目录 = 委派信任面,
也是修订 B「claude 在 git workspace 自主干」从单任务升级到项目级的落点。

三个目标(验收时逐条可证):

1. **声明式流水线**:流水线 = 一段「意图 + 护栏」(YAML 结构化字段 + 自然语言描述 + 工具/凭据引用 + 风险),
   在 Web 控制台编写、落库即生效;**加一条新流水线不写代码**。
2. **高智运行时合成**:每次执行,frontier 模型对「意图 + 该项目可用资源(子目录/凭据/端点档位)」现场合成
   **阶段计划**——拆几段、每段输入/输出契约、分给谁(agent 角色 / 委派 claude / 网关判读)、怎么验收;
   例行流水线用模板化计划(可重现、可比较),高智自由合成只留给非例行。
3. **项目 = 目录容器**:一等实体「项目」= 一个 git 目录(可含 code/、knowledge/ 等子目录)+ 绑定的流水线集合
   + 项目级凭据/环境引用;**该项目所有流水线的 do-stage 只写该目录内**,OS 用既有 git 捕获 + 治理(审批/熔断/审计)兜底。

## 三、目标架构(方向)

```
┌─ 项目 P(一等实体:目录容器 · 唯一委派信任面 · 可含类型化子目录)─────────────────────┐
│   P/code/       代码(开发 / bugfix 流水线的主要 do 面)                              │
│   P/knowledge/  知识库(项目文档/经验沉淀;与 Memory 关系见开放点 6)                  │
│   P/<其他类型子目录…>                                                               │
│   流水线集合(绑 P,只能在此目录内工作):bugfix · 开发 · 运维巡检 …                    │
└──────────────────────────────────────────────────────────────────────────────┘
   每条流水线 = 声明式意图: [YAML 结构化字段(工具/凭据引用/risk/schedule)] + [自然语言描述]
       页面作者面(Phase 7.3 控制台扩展)→ 落库即生效,加流水线不改代码
                                  ▼ 认领/到点
   frontier 运行时合成(8.4 档位前提):对 意图 + 该项目可用资源(子目录/凭据/端点档) → 阶段计划
     阶段 = { 目标 | 输入(前序产出) | 输出契约 | 分配(角色/委派 claude/判读) | 验收方式 }
       计划可审;高风险 / 触碰生产 → 先给人 approve 再执行(复用 approval 门)
                                  ▼ OS 逐阶段驱动
     do 阶段   → 委派 claude 在项目目录内干(简报含子目录边界 + 约束)
     验收阶段  → 能机械验证(测试/构建/证据)→ OS 直接执行当验收;
                无机械判据 → 网关模型判读;不信任 agent 自述(延续 8.2 原则)
     过契约才 advance;不过 → 返工 / 熔断 / 问人(沿用既有语义);全程审计记「计划 + 每阶段产出」
```

**治理口径(方向层定,与既有资产一致)**:文件边界 = 项目目录(委派唯一可写面);
影响边界 = 凭据只读/风险门(碰生产 = 只读优先 + 变更过人的另一个维度)。二者正交,分开写、分开管。

## 四、方向决策(草案候选;每条含取舍,定稿门确认后冻结)

- **D1 项目 = 目录容器(一等实体)**。项目含:一个 git 目录(唯一工作/委派面,类型化子目录 code/knowledge/…)、
  绑定的流水线集合、项目级凭据/环境引用。取舍:OS 收编「散在 task/repo/workflow 的 workspace 概念」到项目上,
  迁移成本换「信任边界一个文件夹、流水线不串目录」。
- **D2 流水线 = 声明式意图,落库即生效**。作者面 = Web 页面(YAML + 描述 + 工具/护栏),新建/编辑不改代码。
  取舍:把「定义流水线」完整搬进数据 + UI;引擎在现 Workflow Engine 之上扩展(节点字段增 schedule/env 引用/
  intent),不另起一套任务形态。
- **D3 运行时合成 = frontier 对意图拆阶段、订 I/O 契约与分配**;但**例行流水线默认模板化计划**(固定检查项,
  模型只解释执行)以保可重现、可跨天比较。取舍:高智合成的自适应 vs 模板的确定性 —— 例行求稳,合成留给非例行。
- **D4 阶段验收分层**:能机械验证的(测试/构建/原始证据)由 **OS 直接执行当验收**,模型判读只用于无机械判据处;
  一切产出不信任 agent 自述。取舍:开发量换「模型批模型自证闭环」这个结构性风险的解除。
- **D5 治理延续**:审批门/熔断/审计/账本/父子聚合逐字复用;`endpoint.tier` 档位(8.4)是合成与分层的硬前提。
- **D6 首期从三类固定流水线形态起步**(bugfix / 开发 / 运维巡检),按项目参数化;等真出现第 4 种再泛化。
  取舍:不做「通用流水线工厂」大抽象,让通用从真实差异长出来(延续用户「不切原生工具、用集成的」务实主义)。

## 五、边界 / 不做(草案)

- **不做 CI/CD**:用户明确暂时不做发布流水线/持续集成。
- **不放开「OS 直连任意外部系统」**:执行仍走委派 + 网关判读;新外部触点以 凭据边界 + 主机 allowlist + 只读优先
  为前置(归 8.3 委派边界及其后续),OS 不自研逐 call 外部编排。
- **不改 0–8 已冻结契约与语义**:回合/端点/审批/审计/API 字段逐字保留;迁移只增不改。

## 六、开放设计点(方向层定口径、实施层再解;草案如实列出,不提前拍死)

1. **验证可信度(模型批模型)**:代码改对没 → 真正裁判是 `go test`/build 跑一遍,不是模型读 diff 说「看起来行」;
   巡检 → 报告内嵌**原始证据**(命令输出/返回码),不收 claude 总结。D4 是口径,落地形态实施层定。
2. **凭据与注入(运维用例的生死线)**:委派进程带生产凭据 + 读项目目录/连外网 → 仓库内一条被污染的 issue/注释
   可能诱导持凭据 agent 越界。方向口径:凭据按项目最小化、只读优先、主机 allowlist、任何变更动作过人。
3. **闭环到真实世界(交付手续)**:委派产出是 OS 目录里一坨 diff —— 谁 review、谁合回上游/开 PR;
   巡检发现 → 谁决定行动(通知→人工 / 自动拉起同项目 bugfix 的**链式触发**)。不做这层会出现「OS completed,
   真实世界纹丝不动」。
4. **预算 / 失控 / 重现**:多阶段 + 合成 + 委派一轮烧钱可大 → 阶段预算 + 全局预算 + 中途取消 + 成本可见;
   非确定性计划 → 例行模板化(承 D3)。
5. **git 布局与提交语义**:项目容器内再放 code,有 布局 A(整项目目录 = 一个 git 仓库)与 布局 B(容器普通目录,
   code 独立仓库)两种自洽走法;多条流水线共享一目录 → **OS 每次运行把捕获 diff 落成本地 commit 保下次认领
   起点干净** + 同目录串行执行(承 8.3 预留的提交/分支决定点,项目制把它逼出来)。
6. **知识库与 Memory 的关系**:knowledge/ 文件为准(委派时可作上下文读)/ Memory DB(FTS+血缘)做索引 / 双写?
   方向口径待定稿确认,倾向文件为准 + DB 索引。
7. **档位前提**:合成要真 frontier —— 若网关只配单模型(修订 A 现状),高智/经济分层名存实亡 → 依赖 8.4 落地真档。
8. **触发源全集与单机现实**:定时 / 手动 / GitHub issue / 巡检发现→拉起 fix 的链式触发;多项目定时巡检若单 worker
   串行,时间账要想清。
9. **UI 复杂度与 MVP**:YAML 编辑器/校验/dry-run 是实打实功能 —— 放实施阶段,首期只做模板化表单 + 描述框,
   不先做通用 YAML IDE。

## 九、风险与取舍

- **高智合成质量绑定 frontier** → 拆错白跑:例行模板化 + 高风险计划先给人批(approval 门),不让模型拆完闷头干。
- **模型批模型 / 自述可信度** → D4 机械验证优先 + 原始证据内嵌;模型判读只兜无机械判据处。
- **凭据泄露 / 注入越界** → 凭据最小化 + 只读优先 + allowlist + 变更过人;8.3 边界是前提,不做就上不了生产检查。
- **工程规模扩张** → 通用工厂一次全做是大工程:MVP 锁三类形态 + 每子阶段独立验收(承 D6)。
- **目录串目录 / 项目间污染** → 项目目录即信任面,流水线不跨项目;同项目内串行 + 每次运行提交保起点干净。
